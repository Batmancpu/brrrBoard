- **Dictate / English-only:** Owner reports the selected Dictate RecognitionService receives speech but outputs Hindi; the user requires English only and no Hindi. brrBoard uses the system-default service and requests English, but Dictate's current service ignores caller language extras and uses its saved Active language. brrBoard cannot alter Dictate's private setting. English-only behavior remains unresolved until Dictate itself is set to English with keyboard-following disabled and owner verifies it on Reno10. Keep brrBoard without INTERNET permission; Dictate may use its own provider/network.
- **Themes:** System-following OG light/dark with one optional Apple-palette action-key tint shipped in v1.0.23. v1.0.24 adds the Shift state vectors. Both need device visual acceptance.
- **Current visual reference:** Only the two screenshots supplied here are current references. They show three prediction slots, center-confidence fill, separate compact right-side accessory, QWERTY rows, outline idle Shift, and Emoji/mic at opposite lower corners. Do not claim frame-by-frame YouTube review. Never commit raw media or typed/clipboard content.
- **Source behavior already present, device acceptance pending:** v1.0.19 reports measured IME host-content boundary, portrait height calibration, toolbar footer parity and 300ms mic hold switching. Alphabetic 123 tap switches to Symbols; hold opens numpad. Emoji hold-and-release menu has three choices; Android/ColorOS owns hide animation. These are source facts, not phone acceptance.
- **Geometry constraint:** Owner uses no visible navigation bar and wants the useless bottom gap reduced without crowding Emoji/mic controls. Code preserves a system bottom inset after the 38dp footer and includes it in host-boundary reporting. Measure actual Reno10 insets, available height, panel bounds and host content before changing it; do not zero insets blindly.
- **Suggestions and proofreading:** Three-slot strip uses decoder-owned `mWillAutoCorrect` for center emphasis; do not invent ranking weights. Android SpellCheckerService is word-level, not Apple's Writing Tools grammar Proofread. Keep the compact accessory separate; no AI/cloud proofreader.
- **Still open:** panel sizing/nav inset, stale tint transition, remaining icons/accessory audit, candidate quality, finite `brrPersonal` Romanized Hindi/Hinglish vocabulary with profanity/slang valid-only, bounded local learning and Emoji mappings, Smart Emoji up to three rows, QuickPath rights/native compatibility, English-only Dictate result, and device acceptance. Do not bundle Apple's ~116MB Emoji TTF or the unlicensed/unverified GlideLib binary.
- **Dictionary baseline:** `main_hi-Latn.dict` is already packaged; settings expose Android User Dictionary and UserHistoryDictionary. The exact 252-word draft from the unavailable prior worktree is unrecoverable. Reuse the existing decoder and verify validity-versus-suggestion behavior before adding another engine or arbitrary weights. Public datasets without clear redistribution rights are not eligible for the APK.
- **Hardware limits:** OPPO publishes Reno10 5G at 2412×1080/394ppi. Runtime dp density, ColorOS build, display/font scale, keyboard height and nav insets are device-only; iPhone 16 Plus is an analogue, not a hard-coded target.
- **CI:** v1.0.24 Obtainium run passed. Automatic debug run [43754830187](https://github.com/Batmancpu/brrrBoard/actions/runs/43754830187) built and signer-verified a debug APK but had 13/180 unit-test failures; no tests were manually launched. Migration run #25 is pending.
