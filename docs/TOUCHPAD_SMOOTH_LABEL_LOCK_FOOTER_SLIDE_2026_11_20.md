# brrBoard iOS-style trackpad polish + filled-Emoji optical balance

## Source and request (20 November 2026, IST)

Owner reports that a long-held spacebar initially produces an attractive label-free surface, but the first cursor move restores all key characters and triggers prediction activity while the finger is still down. Wants the spacebar trackpad to stay blank until release, respond to free two-dimensional movement with an Apple-like feel, and slide the footer Emoji icon **out left** and mic icon **out right** on entry, reversing the slide at exit. Owner likes the filled Emoji and sunglasses, but wants the Emoji optically larger relative to the mic, with a wider hat covering the head. Preserve the previous privacy mic-shield batch, current learnings/model, Original Frosted Glass and Previous Default, and exact main/signing/Obtainium identity.

Apple's public iOS 27 user guide explicitly describes a spacebar hold until all keyboard characters disappear, single-finger drag to reposition the cursor and a second-finger text-selection gesture: https://support.apple.com/guide/iphone/select-edit-and-move-text-iph1a9cae52c/27/ios/27 . Android `InputConnection.setSelection` moves the editor's real caret and triggers `onUpdateSelection`, but third-party IMEs cannot command the host editor to paint Apple's free-floating cursor: https://developer.android.com/reference/android/view/inputmethod/InputConnection . Timings/smoothing below are our original tuneable approximation, **not reverse-engineered Apple private constants**.

## Patch details

- `MainKeyboardView`: on both full keyboard and fast case-switch rebuilds, derive the trackpad label-hidden state from the **live spacebar hold**, not a default `false`. This prevents the `onUpdateSelection` → case switch/keyboard rebuild loop from restoring key legends during a held drag.
- `TouchpadMotionFilter`: small allocation-free filter with persistent fractional `x/y` movement, calibrated sensitivity `16.5..35.5` pixels per letter at endpoints, vertical line threshold `1.4×` horizontal, limited speed amplification (max `1.55×`), and at most three editor actions per axis per pointer callback. Unlike the old winner-takes-one-axis handler, diagonal movement retains both accumulators.
- `TouchpadHandler`: use new two-dimensional motion only for the iOS profile; preserve the old implementation for Previous Default. Update last finger coordinates even while near an edge to avoid a large sudden jump when coming back inside. Reset motion on activation and release; clear stale static mode when a requested but never entered gesture ends.
- `KeyboardActionListenerImpl`: the new touchpad-specific callback batches the horizontal steps into **one** Unicode-aware selection move rather than emitting many generic keyboard events; it also handles vertical line navigation and blocks accidental character/space/popup insertion from another finger. Preserve existing suggestions and typing/learning semantics unless later measured latency warrants a separately discussed change.
- `InputView` → `KeyboardSwitcher` → `BoardFooterView`: keep footer fixed in layout and touch geometry; Emoji slides `-64dp` while the mic, its live turquoise privacy shield/underlight, and password shortcut slide `+64dp`. All fade gently over an original 220ms iOS-profile easing, and use the same reverse path/220ms on exit. Return mid-flight reverses from its rendered position. Disabled, genuinely absent or editor-changing controls must not capture taps. Existing Previous Default preset keeps its prior look.
- `FooterIncognitoEmojiDrawable`: filled icon intrinsic optical size 31→34dp to balance the tall microphone without shrinking or recoloring it; widen/reshape the hat's crown, band and brim but preserve the liked sunglasses and teal-glass reveal. The privacy shield's single shared animation clock remains intact.
- `TouchpadMotionFilterTest` and previous offline mic Python contract add regressions for fractional movement, two-axis diagonals, reversal, limits, sensitivity, privacy-no-restart and no unintended typing.

## Blind spots and actual-phone verification

1. Test one 60-second sustained hold across many words and lines: keys and footers must stay hidden despite autocaps, suggestions and `onUpdateSelection` callbacks.
2. Move horizontally, vertically, diagonally, change direction mid-stroke, slowly crawl, move very quickly, and steer to/from screen edges. Check no stuck movement on finger release, and no sudden leap from stale edge coordinates.
3. Verify emoji slides left, mic and shield together slide right, both restore on lift, cancel, screen change and keyboard recreation; confirm tap areas are inert while hidden and available afterward.
4. Check password fields, secure-app enforced privacy, offline recording, processing, frozen/small app editors, and alternate landscape/layout modes. No new app permissions, model weights, learner resets, signing keys or background work.
5. Swipe immediately from spacebar into another key while a hold is active; second touch must not insert characters or trigger a suggestion acceptance. Apple-style **second-finger selection itself remains an extension**: this patch prevents accidental typing but does not falsely claim full iOS selection API parity.
6. Because an Android IME moves the host app's discrete caret rather than drawing an Apple floating caret, visual/latency feel varies by host app. Physical Oppo Reno10 manual checks are pending; source tests cannot assert physical millisecond motion, cursor artwork or vibrator fidelity.
7. Gate any publish on same-commit debug APK, Android unit tests, Python safety/packaging checks and original-signed Obtainium release. If a run fails, inspect the specific log, repair on main and re-run before reporting an installable result.
