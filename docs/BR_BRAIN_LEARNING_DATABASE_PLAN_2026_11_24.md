# BR Brain learning database — owner request 2026-11-24

## Product design
The private settings header hold + secret code remains the sole normal access path to personal evidence. Build a unified protected inspection dashboard over the existing stores, not one giant raw event table. Adaptive Touch is default ON (existing explicit off respected), always subject to the global personalization/privacy gate. Never capture passwords, protected fields, clipboard, voice text, editor IDs, entire sentences or sequential tap histories. No networking, export of learned personal material in diagnostics, or per-keystroke storage/crypto work.

## Source audit and implementation sequence
1. Adaptive Touch: AdaptiveTouchGeometry has exact keyboard geometry; InputLogic retains up to 32 raw tap positions for a composing word (30s, exact editor epoch); confirmAdaptiveTouch accepts only an explicitly selected aligned suggestion with at most one adjacent substitution. AdaptiveTouchStore currently persists six Gaussian mean aggregates in BrainLearningVault. Extend the same atomic encrypted record from ATP1 to ATP2 with 26 intended-letter entries, 5x5 normalized heat bins and literal-hit mismatch count. One layout signature per geometry, max 12; each letter retains at most 255 decaying samples. Keep the six-region correction model unchanged, expose applied X/Y offset and minimum evidence. ATP1 loads with original trained means, empty per-letter heatmap until actual new confirmation. No historical samples invented. No raw tap strings persisted. The displayed heatmap is not a measured effective hitbox: actual decisions depend on neighbor geometry and confidence. One explicit word selection is evidence of intent, not perfect ground truth. Unify eligibility and training submission through BrSuggestionBrain, retain existing editor and global personalization guards. Default-on for users with no explicit setting; keep opt-out. Add tests for bins, bounded merge, serialized size, malformed data, migration and privacy. Reset clears both aggregate layers.
2. Word-level evidence: owner wants actual intended words. Do NOT silently turn normal keyboard usage into a word logger. Add an explicit protected practice/calibration session using user-entered or reviewed public prompts; show raw literal letters, confirmed intended word, per-letter offsets and candidate decisions during that session. Save a separate optional encrypted bounded set of deliberately saved correction examples only after explicit action; no timestamps, raw tap sequence or context in persistent records. No recording from ambient typing. Review/delete individual examples and reset. Never infer a private word from a tap trace. Actual word history is not delivered by stage 1.
3. Smart library: inspect existing native main/static brrPersonal dictionary sources and dictionary metadata; show language, source, version, lookup results from explicitly entered search, counts only when native API exposes true counts. Do not clone static lexicon or change native lookup.
4. Developing library: native UserHistoryDictionary uses CE native .dict files, not BrainLearningVault; inspect supported native enumeration API and cap on-device queries, allow explicit single-word removal via existing dictionary API; do not dump or parse opaque native mmap files speculatively. Native history encryption migration requires independent crash-safe design; retain authoritative native store until verified.
5. Swipe learning: existing SwipeCorrectionLearner encrypted bounded seed/confirmed word association store; protected dashboard already has real snapshot/counts and limited recent associations. Expand protected paged review/search, count/confidence and explicit single-pair erase, using worker/atomic store. No raw swipe traces. Do not duplicate learned word records.
6. Smart Emoji: existing BrrSmartEmojiEngine local encrypted selection associations + reviewed phrase cues/recents. Add protected bounded association and count inspector with provenance, explicit delete, no raw preceding text. Distinguish reviewed static cues and learned associations.
7. ContextLM: BrContextLmExperiment existing local scoring metrics, public-trained INT8 weights and manual-only reranker; show actual model version, quality gate status, bounded scores on deliberate sample, aggregate latency and candidate rank-change counts. No automatic activation of failed model. Core native prediction stays immediate. Shared BrSuggestionBrain coordinator uses typed adapter contracts, privacy and exact-editor generation; use dictionary confidence and explicit correction to validate touch evidence, do not route every tap through neural inference.
8. Correction memory and undo: RAM-only 30-second state, inspect counts and expiry without persisting original words or undo payloads. Text tools, templates, rules and app profiles retain distinct encrypted/settings stores with explicit controls; no implicit learning from clipboard, protected text or microphone. Diagnostics include only content-free operational timings; no heatmaps, words, secret IDs or data dumps. Each inspector only rendered in authorized foreground session; auto-lock and secure window remain. Add deletion and storage-health statuses; use explicit opt-in for anything beyond aggregates.
9. Tests/release: exact-source debug and original signer gate, keep main only. Device test on Reno10: manually confirm words, review new heatmap, restart, verify existing model persists, reset, incognito and secure app yield no evidence, check latency. Compare key-to-frame timing and accuracy before/after; no unmeasured Gboard parity, real hitbox or accuracy claim.
