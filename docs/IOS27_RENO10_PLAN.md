## Wallpaper tint, curved edges and touch

- Keep the iOS Tinted backdrop white Frosted Glass. Letter keys and regular controls stay neutral. For the action keys and states visibly accented in the iOS references, take the Android 12+ system dynamic accent and match it to the nearest appropriate Apple system swatch by perceptual color distance. The blue Search action is the confirmed example. Ordinary Return stays neutral. Fall back to the reference action color if dynamic accent is unavailable.
- Apply the selected color only to the highlighted key. Keep the blur, glass tint, neutral keycaps, and suggestions independent of wallpaper colors. Verify readability of the key label or glyph and contrast on bright and dark content. Keep iOS Clear and OG default independent. Derive and cache the action color on theme/configuration changes.
- Tune the outer shell and keycap corner radii separately. Use the current IME width and safe navigation insets to place the footer away from curved edges. Clip the glass to the shell, preserve full key touch targets, and check for edge distortion or dead zones on the Reno10.
- Use immediate pressed states and the existing haptic setting, with short release transitions and a spring on the drag release. Keep primary key input immediate, skip extra effects with reduced motion, and verify repeated taps and low frame rates. Smart keys, clipboard eligibility and suggestions use local rules and dictionaries. No new AI features.
- References: [Android Material 3 dynamic color](https://developer.android.com/develop/ui/compose/designsystems/material3#dynamic_color) and [Apple system color guidance](https://developer.apple.com/design/human-interface-guidelines/color).

## Implementation and commit order

1. **Mic repair.** v1.0.8 owner footage shows a light Listening/Stop/Cancel panel flashing, then the missing-model message. Permission checks passed on the path that reports this message. Inspect the actual requested locale and distinctions between ERROR_LANGUAGE_UNAVAILABLE and ERROR_LANGUAGE_NOT_SUPPORTED. Check exact request support on supported Android/service versions, handle unsupported support checks, and let the user pick an installed compatible locale explicitly if necessary. If the device lacks a usable provider, investigate a bundled offline engine separately against APK size, licensing, latency, battery, and English/Hindi compatibility. Keep the existing on-device-only constraint. Use a themed stable toolbar status with Listening only after readiness; confirm cancel/stop and discard stale results after focus changes. Verify insertion in ordinary and search fields in airplane mode; verify protected editors and log only error/locale metadata if diagnostics are needed.
2. **Layout, symbols, icons and presets.** Use existing layout/parser, key rendering, settings, and color paths. Make default alpha row 123 / space / editor action. Add separate footer globe left and mic right. The globe cycles enabled brrBoard language subtypes on tap; preserve access to the Android IME picker for switching to Dictate, via the system switch and a keyboard-accessible picker action. OG default restores backup-derived appearance/layout/IME-switch behavior in one action without clearing dictionaries, clipboard, or learned words. Keep a user's current preferences available before activating a preset. Implement distinct iOS Clear and iOS Tinted appearance presets using the Frosted Glass renderer with controlled transparency and readable contrast. iOS Tinted has a white glass tint with wallpaper accent limited to iOS-highlighted actions; optional number row remains independent. Use a small brrBoard caption anchored at the lower-right of the spacebar, following the screenshot placement of EN/ES. Map the footer mic to the repaired inline action. Move the toolbar control to the right end of the suggestion strip and use an A-style mark with a descriptive accessibility label. Keep three compact local suggestions when available, with subtle dividers. Inspect earlier PR #6 before borrowing geometry.
3. **Toolbar drag.** Start tracking in the whole strip, wait for downward touch slop and vertical axis lock, cancel the underlying tap on capture, and translate the keyboard surface (including blur) with the finger. Use half the visible keyboard travel as the starting dismissal threshold because the existing callback hides the IME. Spring back on early release or cancellation, finish one dismissal when past threshold, and respect system animation settings. Resolve with upward more-suggestions, horizontal scrolling, long-press/reordering, and open popups. Verify left, middle and right start points, including over suggestions and the toolbar button.
4. **Globe hold menu and contextual controls.** On hold show a compact, translucent rounded arc of Emoji, Clipboard, Settings above the globe, with safe-edge placement, live highlighting and release-to-select. Release outside cancels. Reuse the existing actions and defer activation until release; provide accessible tap actions for users who cannot drag. Use runtime EditorInfo/inputType and action flags for contextual keys. Email gets @ and period; URL gets slash/period with relevant domain shortcuts if supported; Search, Go, Next, Send and Done follow the host's declared action. Numeric/phone/password keep their purpose-built layouts. General text and search use the editor action in the normal three-key row; email/URL are deliberate exceptions. Use the existing clipboard pipeline for a fresh plain-text paste chip while the editor is eligible, with explicit tap to paste, expiry/dismissal, no sensitive preview, and priority that yields to active word composition. Revalidate editor and clipboard state on tap. Preserve normal offline suggestions and keyboard accessibility.
5. **Device and release checks.** Finger-follow and popup lifecycle, popup placement near screen edges, TalkBack, rapid typing, spacebar cursor gesture, shift/caps/delete states, symbols/currency, email and URL variants, search action, clipboard gating, preset round trip and performance on ColorOS. Compare screenshots of the same editor states and assess animation on physical hardware. Compare the known 14 baseline debug failures and investigate any new failures (layout, currency, space/URL, and emoji behavior are particularly relevant). Validate upgrade from v1.0.8, higher version code, existing package and signer, retained settings/dictionaries, and absent network permission. Produce a signed checkpoint after each validated phase through the existing pipeline. Update AGENTS.md, PROJECT_CONTEXT.md, and the conversation record with each result and pending device check.

## Code audit pointers

- In v1.0.8, InlineDictation adds a temporary theme-derived panel before onReadyForSpeech, while its onReadyForSpeech callback does nothing. Error paths remove the panel, and two model errors share the same toast. Repair session state before relocating the mic.
- SuggestionStripView currently uses a fixed 50 dp cutoff in its MoreSuggestionsView detector. LatinIME.onSwipeDownOnToolbar calls requestHideSelf. Keep this final action while replacing the gesture intake and rendering.
- Defaults uses language_switch_key=input_method. SettingsValues already distinguishes switching to other IMEs and internal subtypes. Do not globally overwrite the owner's selection when adding the iOS profile.
- ClipboardHistoryManager already has a recency path and a suggestion view. Audit its plain-text sensitivity and editor guards before using that view in the revised toolbar. Avoid changing history or paste behavior outside this path.
