# Emoji compact Browse / expanded header / Search footer — 2026-11-18

## Owner evidence (do not overstate)

- New 18.13-second Oppo video (512×1140, 30 fps): in compact Browse, the category row is visible but a stationary transparent/blurred band occupies the area above the first normally visible emoji row. Emojis move below that boundary and at least one row appears cropped. Search input/results work; intentionally expanded Browse displays more intact rows but retains an unwanted Search bar/Collapse icon. Video alone does not identify Android's actual measured view coordinates.
- First still: during **Emoji Search typing**, the ABC/mic footer shows highly saturated colors from the hidden Emoji grid. Second still: after returning to regular alphabet typing, the footer correctly stops showing those Emoji colors.
- Owner confirms v1.0.109's one-time `scrollToPositionWithOffset` correction **did not** solve the physical top-row problem. Do not mark it fixed because tests pass.

## Source findings and corrective design

1. **Two independent vertical origins:** `strip_container.xml` put categories in `main_keyboard_frame` OUTSIDE `keyboard_view_wrapper`; `emoji_palettes_view.xml` put the virtualized grid INSIDE a separately measured, bottom-gravity `EmojiPalettesView`. `EmojiPalettesView.onMeasure` also varied body height depending on whether the external strip was visible. Past patches adjusted saved row offsets, root height and RecyclerView top padding individually; none guaranteed that fixed categories and the first visible emoji share one layout origin. This is a verified structural source conflict consistent with the video, not a measured proof of the exact 50–100px gap on Oppo.
2. **Top internal glass missing:** `emoji_header_scrim` was XML `GONE`, configured but never made visible, and the category strip used suggestion-strip background plus `STRIP_BACKGROUND` on every tab. Thus the requested real emoji-behind-categories blur was impossible in Browse.
3. **Expanded mode's extra controls:** `exitSearchMode` explicitly made `mSearchBarContainer` `VISIBLE` when `mExpandedMode`, explaining the unrequested Back/Search/Collapse row.
4. **Search footer ghost:** `InputView.onMeasure` passed `emoji_pager` to `BoardFooterView` whenever outer Emoji view was visible, **even when Search had made the pager GONE**. `PanelGlassOverlayView.onDraw` could manually `draw()` that hidden pager into a RenderNode because it only checked attachment/size, not `isShown`. This directly explains the still of stale emoji color under Search's ABC/mic.

This batch moves the **existing** category container to the top of `emoji_grid_shell` as the highest fixed sibling, with no duplicate Search pill and with the original Search/Space/Delete row untouched. The shared outer suggestion strip is GONE in Emoji Browse (including Search→Back); `EmojiPalettesView` recovers its height in the body. Each category RecyclerView now reserves exactly the fixed header height plus 8dp as initial top padding, with `clipToPadding=false`, allowing rows to scroll behind the categories. The top `PanelGlassOverlayView` takes its sample from the actual pager; `EmojiGlassFrameLayout` clips only the *sharp* pager above the header bottom, leaving the source fully scrollable for live blur. Transparent category tab surfaces and the selected-circle renderer stay above glass. The same user-controlled emoji-only tone applies to the top live internal pixels; it does **not** repaint the host wallpaper.

Expanded Browse hides its Search bar completely. The native bottom Search key still enters Search typing; the right-side Expand/Collapse action remains in Search, and Back can collapse expanded Browse. Recents contextual suggestions are hidden during Expanded Browse; compact Recents contextual behavior remains unchanged. Emoji Search footer now gets `source=null` (clears prior RenderNode) while the hidden pager cannot be sampled, and the general glass renderer independently refuses hidden sources.
