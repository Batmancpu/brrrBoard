# brrBoard — high-accuracy North Indian English offline voice: integration and one-time model migration

**Date:** 2026-11-20  
**Status:** **PLAN / DESIGN ONLY — NO IMPLEMENTATION AUTHORIZED.** Owner will explicitly say **“go”** before source, model, build-workflow, APK, or device changes. The current task authorizes only this plan and repository handoff documentation.  
**Repository:** `Batmancpu/brrrBoard`, `main`. This is an independent future voice-engine batch; do not treat older GOs for Settings, UI, brrSpeak, or mic animations as a GO for this proposal.

## Owner contract and one decision

The target is **the highest practical on-device transcription accuracy for spoken English with a North Indian accent**, with everyday keyboard responsiveness and zero online ASR in the blue/private mic route. The selected **integration candidate** is **Moondream Parakeet Ultra, 0.6B parameters, official sherpa-onnx INT8 ONNX export** (`csukuangfj/sherpa-onnx-nemo-parakeet-tdt-0.6b-ultra-int8`), running through a verified new `sherpa-onnx`/ONNX Runtime arm64 Android build.

**Important qualification:** 0.6B means *600 million parameters*, not exactly 600 MB. Expect roughly **600–700 MB-class** model assets before APK/runtime overhead; exact revision, compressed APK size, model-file sizes, and SHA-256 hashes must be measured and pinned at implementation time. No honest benchmark yet proves Ultra is the best for this owner's *North Indian English on an Oppo Reno10 5G*. The model author's English OpenASR average was 5.80% WER (versus 6.26% for NVIDIA v3) under its own GPU/Photon protocol; sherpa-onnx's separate FLEURS-English export test reports Ultra 8.51% against Parakeet v2 6.48% under a different protocol. These comparisons cannot be mixed. **Do not promise an accuracy gain until a same-audio Indian-English A/B test on target hardware confirms it.**

**The owner's one-time package requirement is binding:** the **first migration APK must contain all new Ultra weights**, must install **in place** over the current application, must import and validate the new engine entirely locally, and must **remove the previously installed 110M Parakeet weights after successful migration**. All **subsequent routine APK updates must omit model weights**, but reuse the model persisted in private `noBackupFilesDir`. No automatic on-phone download, silent provider substitution, reinstall, data clear, or new INTERNET permission. If the special APK has not successfully extracted and activated Ultra, do not delete the old model. This is a transactional transition, not indefinite dual-model storage.

Keep the existing package identity **`com.mangoloads.board`**, original release signing certificate, monotonic `versionCode`, Obtainium installation/update compatibility, current brrBoard/brrSpeak separation, all user dictionaries and preferences, encrypted learned data, protected-editor/incognito semantics, and mic UX. The blue held mic stays 100% offline. The existing red brrSpeak/provider mode and its explicit **Paste offline** fallback remain separate; the offline fallback may use the same new local decoder once it is verified. No app/source/CI/release modification occurs before the owner's new GO.

## What is already in the repository (verify again at GO)

- `app/src/main/java/helium314/keyboard/latin/voice/VoiceModelManifest.kt` fixes the **110M English INT8** ID, paths, four SHA-256s, and assets (`encoder.onnx`, `decoder.onnx`, `joiner.onnx`, `tokens.txt`), total **136,490,421 bytes**.
- `VoiceModelInstaller.kt` copies bundled assets to `context.noBackupFilesDir/voice-models/<ID>`, hashes them, writes a verified marker and renames the staging directory. `isInstalled()` presently trusts the marker plus sizes on subsequent checks. Its existing destination deletion must **not** be reused against an active older model during migration.
- `OfflineVoiceEngine.kt` is a singleton-ish worker and cached offline transducer, using `nemo_transducer`, a pinned sherpa native runtime, 16 kHz PCM, two threads, a 90-second idle unload and `VoiceSegmenter`/`VoiceTranscriptJoiner` for chunks. Both blue dictation and the red-mode backup share it. It does **not** yet have live personal hotword biasing.
- `VoiceSegmenter.kt` currently chooses low-energy, 11-second-target/15-second-maximum windows with 250 ms overlap. Rework only after measuring boundary quality against VAD, rather than stacking two competing segmenters.
- `tools/offline-voice-model.lock`, `tools/prepare-offline-voice-pack.sh`, `tools/verify-voice-model-packaging.sh`, `tools/verify-bundled-voice-model.sh` and the Android release workflows pin/fetch/verify the current model. No model weights should enter Git history.
- `.github/workflows/obtainium-release.yml` has a manual `bundle_voice_model` switch, false by default; normal pushes omit weights. **Audit finding:** its release command currently uses `--latest` even for the manually bundled variant and names the output `brrBoard.apk`; the existing historical narrative saying the bootstrap is non-latest is not a reliable implementation guarantee. This must be fixed, with a dedicated, clearly named one-time full APK that Obtainium cannot mistake for every ordinary incremental update.
- Project-wide strict privacy, `EditorInfo`/editor generation guards, cancellation, red/blue mic visual distinction, native Android/UserHistory/brrPersonal dictionaries, and original signing gates already exist. Read latest `AGENTS.md`, `PROJECT_CONTEXT.md`, `docs/ENGINEERING_HANDOFF.md` plus live code at GO; do not assume historic documented paths or state are unchanged.

## Implementation architecture (execute in isolated, reviewable batches only after GO)

### A. Lock the **specific** Ultra artifact and Android runtime

1. Pin the **official** `csukuangfj/sherpa-onnx-nemo-parakeet-tdt-0.6b-ultra-int8` export to an immutable upstream commit/archive and record license, provenance, exact filename, byte count, and SHA-256 for `encoder.int8.onnx`, `decoder.int8.onnx`, `joiner.int8.onnx`, `tokens.txt`. No `main`/moving-latest fetch at release time. Confirm encoder graph/metadata and TDT joiner are compatible with `model_type="nemo_transducer"`.
2. Implement a *new, versioned* model manifest/lock rather than overwriting the previous manifest before the new installation has passed its checks. Keep old manifest solely for controlled migration/temporary rollback, not as a permanent second production engine. `MODEL_DIR` must be unique. Choose an app asset naming convention that yields predictable installed paths and verifier behavior; source ONNX filename may be mapped inside app after exact hash verification.
3. Upgrade the currently pinned sherpa-onnx Android native runtime **only to an exact validated release/commit** carrying the October 27, 2026 NeMo-TDT `modified_beam_search` speech-drop fix (upstream PR `#4084`), if using that decoding mode. Pin AAR/JNI checksums and ABI, test Android 15/ColorOS and **16 KiB ELF page** compatibility; use ONNX Runtime CPU, not an untested LiteRT/GPU switch. Validate license notices and binary/asset provenance. If a compatible fixed Android build is unavailable, retain *greedy search* and defer hotword beam search until verified.
4. Profile target phone memory, model load/warm time, cold start, thermal throttling, and CPU threads (start at 2, evaluate 2/4) rather than inferring desktop throughput. Lazy-load once on worker, reuse for nearby utterances, release under memory pressure, never load full model on the UI thread; cancellation must stop unnecessary compute and release temporary buffers.

### B. Audio quality, endpointing and decoding

1. Retain **one** foreground AudioRecord/PCM16 capture owner. Normalize/resample properly to mono 16,000 Hz and `float32` input; use robust audio-source selection, clipping checks and gain normalization for quiet speech, without blindly enabling OEM noise suppression or dropping unvoiced consonants. Preserve the existing blue-in-RAM-only / red-explicit-provider privacy routes. No network fallback from blue.
2. Measure current low-energy chunker against a small, independently pinned **Silero VAD** (ONNX) and choose a single best segmentation policy. Use conservative pre-roll/trailing padding, silence-aligned 15–20 s maximum segments, a short overlap and word-boundary join deduplication. Do **not** cut at fixed timestamps or truncate quiet/fast North Indian English. VAD cannot identify language; only an evaluated policy decides whether to reject very short silence/noise.
3. Baseline is TDT **greedy search** with confidence/empty-speech checks. In a separate A/B experiment enable **modified beam search** and bounded hotwords only with a fixed sherpa release that includes `#4084`; tune `length_reward` experimentally (0.5 was useful in the upstream reproduction, **not proven optimal for Ultra**), beam width, and conservative hotword score. Automatically fall back to baseline if missing words, hallucinations or p95 latency worsen. Never pretend that a CTC decoder, WFST graph or external KenLM language model is automatically compatible with Ultra's TDT head: changing to CTC would require a distinct trained/exported model and an independent evaluation.
4. Keep transcript insertion, punctuation/casing, and text correction separate. Apply limited, local punctuation, common number/date formatting, safe acronym proper-casing, and high-confidence lexical corrections; avoid semantic rewriting, forced Hinglish transliteration, double commits, duplicate segments and aggressive autocorrect. The language target is English, but keep *all existing keyboard dictionaries and multilingual typing behavior* intact.

### C. Privacy-first **personal vocabulary**, not magical acoustic self-training

1. Build a small, bounded English-context lexicon from already approved sources: brrPersonal static vocabulary, Android User Dictionary, and **existing consented/encrypted** UserHistoryDictionary entries. Preserve source weights/provenance. Treat domain terms (UPSC, place names, Indian names, technical words, user-created spellings) preferentially, but de-prioritize common everyday words that could cause hotword hallucinations. Do not scrape arbitrary app text, clipboard, passwords, contact lists, secure-app editors, or whole draft documents.
2. At eligible non-private dictation start, rank at most a deliberately bounded set of relevant terms by local count/recency/explicit user pinning and language, then tokenize using **the model's own `tokens.txt` vocabulary**. Verify exact sherpa hotword format/availability. Prefer an in-memory token/trie/JNI interface; **do not silently dump decrypted personal text to a persistent plaintext hotwords file**. If the pinned API only accepts a file, implement and security-review an ephemeral private-scope path and strict wipe/cleanup, or ship without *personal* beam hotwords until an acceptable privacy-safe route exists. Static nonpersonal vocabulary may be used separately.
3. Capture user *confirmed corrections to a just-inserted voice span* only while the same editor/session and consent are valid. Keep attribution/session metadata ephemeral; rank the corrected spelling higher in the encrypted local dictionary over time, with bounded frequency, decay, undo and clear options. Keyboard typing may independently reinforce words through existing opt-in dictionary policy. Never learn from incognito, password/sensitive `EditorInfo`, secure apps, rejected/cancelled utterances, failed/partial transcriptions, or the brrSpeak server path without explicit design review. Never store raw audio/transcripts by default or log word content.
4. Be precise: written-vocabulary adaptation can improve **word selection**, *not* the model's acoustic ability to understand this owner's pronunciation. True accent adaptation requires opted-in paired speech and corrected transcripts and a separate offline model fine-tuning effort; **out of scope** for this integration. Keep language-list/ranking changes independent from native prediction, swipe, Emoji and punctuation dictionaries.
5. Make features inspectable and reversible: status for “Offline Ultra ready / Installing / Missing / Failed,” a privacy-readable “Personal vocabulary for voice” control following existing learning consent, clear/remove learned voice corrections without touching unrelated native dictionaries, and no background/network model provisioning.

### D. The **one and only** 600–700 MB-class APK install, then lightweight updates

1. Add a **manual, explicitly named** `Ultra bootstrap/migration` release mode to existing original-signed CI. The full one-time APK embeds **only the new Ultra model** (not old Parakeet 110M), sherpa runtime and code. Its build verifies every upstream file size/SHA-256 and signed APK asset; normal builds must fail if *any* ONNX model weights appear, and bootstrap builds must fail unless **all** Ultra files are present, with no old-model assets. Do not commit weights to Git. Keep build input/checksum repro, explicit CC-BY-4.0 attribution, provenance and license notice in release metadata.
2. Fix the **observed existing `--latest` hazard**: a manually dispatched heavyweight APK must have a distinctive downloadable name and a distribution/release track that does not become the automatic Obtainium lightweight latest. Define monotonic `versionCode` across both tracks and require the *next* normal lightweight version to be strictly higher than the one-time bootstrap. Audit Obtainium asset matching and GitHub `--latest`/prerelease behavior on a disposable test configuration; never rely solely on what a document previously promised. Do not replace the ordinary `brrBoard.apk` unexpectedly.
3. **Safe migration order on the phone:** same-signer in-place install → verify minimum free storage → detect old 110M verified directory → extract bundled Ultra to *unique* `.installing-ultra-<version>` inside `noBackupFilesDir` on a background worker with progress → verify full byte counts, SHA-256 and `fsync` → atomically promote the new directory and active-version pointer → load decoder and run synthetic *non-private* health input locally → mark `READY` → switch both local dictation callers to Ultra → **only now** remove the exact old `voice-models/parakeet-tdt-110m-en-v1` directory and stale model-specific stage files. Do not touch learning/keys/other voice data. Recovery from crash/out-of-space must restart safely without deleting the old model; no generic recursive cleanup outside explicitly validated private model paths. On successful migration there should be **one** model directory, Ultra.
4. Before activation, test the old route remains operable in a failed migration; after activation, test Ultra works without the bundled APK present. Do not promote if the new runtime cannot open the quantized model. For a failed post-activation load before old deletion, roll back active pointer to the verified old model. Once the old weights are intentionally deleted, rollback to that old **recognizer** requires a separately owner-authorized recovery installer; normal user text, model and learning data must still survive updating.
5. All later **ordinary** `main`/Obtainium APK releases contain **zero model bytes**, continue to reference the same Ultra model ID and private path, and never try to delete/re-extract it. When an optional future Ultra revision is considered, it is **another explicit owner decision**, not silently bundled/downloaded. In-place update must not uninstall, wipe app data or change signing keys. Clearing app data/uninstall erases model and requires explicitly requested recovery; display `MODEL ABSENT` truthfully. Plan enough *temporary* device storage for APK download + package install + staged Ultra copy + existing 110M; measure minimum actual space rather than claiming an unverified fixed GB.

### E. Acceptance gates — must pass before any claim of “best” or any default promotion

**Research gate before GO implementation:** compile a 150–300-clip consented, held-out North Indian English evaluation set (several speakers, normal/fast/quiet speech, accents from different North Indian states, office/noisy room, Indian names and acronyms, numerals/dates, sentences of 3–15 seconds and longer speech). Use synthesized public/nonpersonal snippets for CI; private evaluation material stays off public GitHub and is deleted/handled as agreed. Benchmark the existing **110M** and **Ultra INT8** against *identical* audio, with identical normalizer and word error rate (**WER**), plus separate proper-noun/entity accuracy and hallucination/omission counters. Optional public Svarah Indian-English evaluation is useful but not a North-India-specific proof.

**Target, not claimed result:** at least **15–20% relative WER reduction** versus brrBoard's own 110M on the owner's accent collection; no worse high-value names/numbers; no significant added hallucinations; measured p50/p95 time from stop to insertion, peak RSS/PSS and thermal behavior acceptable on the Oppo Reno10 5G (8 GB class), including long sessions. Reject or retune hotword beam mode if it worsens general text. If Ultra misses this target, **do not mislabel it 'best'**; report the measurements and request a new decision before replacing the current engine.

**Safety/release gate:** targeted model-manifest, extraction-crash, checksum corruption, low-storage, power-cut/restart and old-model-removal tests; decode native smoke and short/long WER harness; incognito/secure-editor, dictionary isolation, personalization delete, non-consented text/audio/no-logs, zero new network permission; VAD boundary/dedup, cancel/restart, mic gesture animations, editor change during decode, double insertion and red-mode provider independence. Run exact-source debug/full Android unit + original-signed Obtainium workflow to **terminal success**, verify signer, package, version, APK SHA and embedded model manifest, with **manual special bootstrap** and a **subsequent normal lightweight APK** independently exercised on the real phone. CI alone is not on-device acceptance; owner confirms the accent, speed, storage and update experience.

## Execution batches after the owner's explicit future “go”

1. **B0: source and metric baseline.** Refresh `main`, sign/ABI/model paths, obtain consented held-out test audio or owner-provided comparison, measure existing 110M and new INT8 offline on target device. Stop if unacceptable or unbuildable; leave app installed.
2. **B1: pinned Ultra model + runtime only.** Add manifest lock, verify downloads/hash/license, compile native Android/synthetic decode under CI; **no deletion or published migration APK yet**.
3. **B2: capture/segmentation and inference fidelity.** Build safe VAD option, long-clip boundaries, worker memory, cancel/insert correctness; benchmark against baseline and tune thread count.
4. **B3: measured contextual vocabulary.** Add bounded private dictionary/confirmed-edit learning and opt-out path; A/B greedy against fixed modified beam + hotwords. Keep defaults conservative until Indian-English WER/entity tests justify changes.
5. **B4: transactional one-time full APK and cleanup.** Add special CI packaging, robust migration/rollback and model READY status; test full-to-lightweight in-place updates on staging device before original signed public bootstrap. Only upon verified Ultra activation delete old private 110M files. Future routine releases exclude weights.
6. **B5: owner Oppo acceptance and durable handoff.** Test airplane mode, quiet/natural/noisy speech, proper nouns, red/blue fallback, storage and updates; publish only with both exact-SHA CI gates and owner acceptance recorded distinctly; preserve rollback instructions and source attribution.

Each batch must record touched paths, purpose, independent test results, exact source SHA, CI run IDs and terminal outcomes, signed APK package/cert/version/checksum if built, real-device acceptance separately, remaining risks, and explicit *what is not yet implemented*. No feature creep into Settings, MangoLoads branding, Emoji/Clipboard, native swipe, protected-app policy, brrSpeak authentication, or signer.
