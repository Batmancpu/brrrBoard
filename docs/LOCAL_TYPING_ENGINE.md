## Existing prediction, personalization and packaged data

- Typing and previous-word context flow from InputLogic and WordComposer through Suggest.kt and DictionaryFacilitatorImpl.kt, including native dictionary sessions, keyboard proximity, locale confidence and separate spell-valid/suggestion-valid queries. `app/src/main/java/com/android/inputmethod/latin/BinaryDictionary.java` marshals x/y/time/pointer data, composed code points, NgramContext and options through JNI. `latin/SuggestedWords.java` and Suggestions separate candidates from editor application. The correction, backspace undo, capitalized variants and URL/email logic live in InputLogic. Use the existing transaction/commit path for typed and generated suggestions.
- DictionaryFactory and DictionaryFacilitatorImpl load main, Emoji, user and optional app/contact/history dictionaries where enabled. Preserve locale confidence, dictionary blacklist and legitimate user entries. Source packages English US/UK and Roman Latin Hinglish (`hi-Latn`) for production, plus `emoji_en-IN.dict` and `emoji_hi-Latn.dict`. Internal subtype and test dictionary catalogs intentionally remain broad. Historical v1.0.40 subtype trim caused eight extra failures before v1.0.41 restoration.
- `latin/dictionary/BrrPersonalDictionary.java` loads a versioned expandable native cache from `brrPersonal.tsv`, with English/Hinglish use controlled by DictionaryFacilitatorImpl. It seeds up to 6,000 PHINC-derived static terms with unigram frequencies and reviewed verbatim-token Emoji shortcuts from `app/src/main/assets/brrPersonal_rules.tsv`. Rules pin valid-only slang/profanity out of proactive text suggestions even when it is intentionally typed. `tools/prepare_brrpersonal.py` pins PHINC source 44b5471df75e508b9d6fcdbcc93df04bb1e84056 and `app/build.gradle.kts` generates TSV at preBuild, which can need build-network access even though IME runtime is offline. Review asset licensing and NOTICE and preserve three static backup dictionaries already bundled. Archived learned user history is private and stays on-device. [PHINC dataset](https://huggingface.co/datasets/LingoIITGN/PHINC) · [PHINC paper](https://aclanthology.org/2020.wnut-1.7/)
- Current Smart category is indexed as ID_RECENTS. `EmojiCategory.java` (L163+) migrates default from Smileys and resolves fallback. `EmojiPalettesView.java` AdaptiveEmojiEngine scores usage count, recency and other local boosts, and updateAdaptiveEmojiOrder inserts ranked items in Recents display. v1.0.54 made first-use population. v1.0.55 ranked a copy of decoder-provided Emoji in `SuggestionStripView.kt` only when at least two are present (`setSuggestions`, L561+) using usage rank. This explains why selecting Smart can feel like Recents and why some strip Emoji nevertheless respond to typed text. Smart grid itself lacks composing-token relevance. Implemented history/adaptive paths are useful guardrails; preserve them.
- Emoji semantics vs rendering are independent. `tools/make-emoji-keys/` contains Emoji 13.1–17.0 test data and Android availability model. `SupportedEmojis`, `latin/common/StringUtils.kt`, EmojiCategory, EmojiPageKeyboardView and localized Emoji dictionaries split availability, single-grapheme recognition, picker placement and keyword lookup. A Unicode code point or valid sequence does not prove an installed system font draws it as one glyph. Keep exact insertion sequences, variation selectors, ZWJ, skin tones and flags. Match canonical display IDs separately for stats. [UTS #51](https://www.unicode.org/reports/tr51/) · [UAX #29](https://www.unicode.org/reports/tr29/) · [Unicode data license](https://www.unicode.org/license.txt)

## Recommended local text quality plan

| Option | Value | Decision and bound |
| --- | --- | --- |
| Current AOSP-format dictionaries, NgramContext and device-local learner | Native proximity/space-aware scoring and existing editing behavior | Keep them. Baseline US/UK/hi-Latn and downgrade/reset scenarios before data or thresholds change. |
| PHINC plus reviewed Indian English / colloquial aliases | Gives local spelling-valid Hinglish and adaptable frequency; PHINC is a parallel corpus with limited modern slang coverage | Keep pinned existing source. Add a small attributable curated seed for current phrases and transliterations, cap frequency by source, separate spelling-valid from predictive eligibility and build deterministic assets. |
| English Speller Database/SCOWL | Dialect and spelling-variant lists | Optional spelling-validation supplement, if provenance, license and product value justify. Word lists alone do not learn sentence frequency. [ESDB](https://wordlist.aspell.net/) |
| Public n-gram word frequency corpus | Can improve next-word rankings | Offline-only experiment. Check redistribution for derived counts, language/domain bias, normalization and split leakage. Do not ship raw social text. Prefer existing unigram engine plus constrained n-gram asset if logs justify benefit. |
| On-device neural or cloud generator | Adds models, memory/latency, privacy and update surface | Outside selected design. The evidence supports improving existing decoder and small offline data first. |

1. Establish a stable phrase/word evaluation set independent of generator training, with English US/UK spelling pairs, Indian English, Romanized aliases, common informal shorthand, unfamiliar names, deliberate slang, punctuation, apostrophes, typo classes and URL/email strings. Use authored synthetic sentences and properly licensed corpus segments assigned to disjoint train/development/test sets by original sentence or source. Keep owner typing out of files and logs.
2. Instrument aggregate candidate recall@3, top-1 next-word, accept/undo correction rates, false autocorrection on in-vocabulary proper names/slang, latency by cold/warm path, and heap. Pair with fixed EditorInfo variants. Hierarchy: preserve exact entered forms in private/URL/email fields and user-corrected validity, honor user subtype, cap lowercase normalization to lookup, keep shown case and accents, apply autocorrection only above a margin from literal and runner-up.
3. Change one factor per batch: lexical validity/frequency profile, n-gram ranking, then correction thresholds. Preserve caps, punctuation, undo, word-boundary handling and user learning semantics. Do not remove English alternatives or teach valid-only slang via proposed candidates. d1f8aff restoration and v1.0.53 payload trim are boundaries.
4. Keep adaptive history distinct from static rules. Respect incognito, password, visible-password, no-personalized-learning and local learned-data reset. Confirm reset across caches, active IME, restart and persisted objects and intentionally keep explicit personal dictionary distinct unless user deletes it. Provide test controls with synthetic data. No per-keystroke IO or network.

## Smart Emoji — planned data and ranking contract

- Data generation: pin one stable CLDR release compatible with chosen Unicode/Emoji dataset. Create a compact search index from English CLDR names/keywords, add reviewed Romanized Hindi/Hinglish and slang phrase aliases. CLDR specifically distinguishes broad search keywords from reliable typing triggers. Use broad metadata for search; use narrow scored trigger rules for contextual suggestions. Maintain source version, license, attribution, locale, reason and curated allowlist per override. Inspect malformed and unsupported sequences during generation. [CLDR annotations](https://www.unicode.org/reports/tr35/tr35-general.html#Annotations) · [CLDR source](https://github.com/unicode-org/cldr)
- Snapshot only permitted composing token plus a short suffix of last committed in-memory tokens (e.g. up to four). Normalize case/punctuation for lookup without rewriting editor text. Exact phrase and exact keyword allow replacement or append by explicit candidate metadata. Example synthetic test: “happy birthday” → 🎂/🎉, “good night” → 🌙/😴, “yaar mast” → 😎/🔥 when curated; short ambiguous tokens require higher threshold. Match on token boundaries, cap input and candidate count, avoid trigger from partial email/URL/code, abusive text or no-personalized fields. Stop evaluating on editor switch. Avoid reading arbitrary field contents if foreground InputLogic has the needed composing context.
- Candidate order: exact curated phrase > exact unambiguous phrase/name > curated single-token aliases > supported dictionary Emoji shortcuts > session/local use only as a bounded tie-breaker. One possible scoring scheme starts at 5/4/3/2 respectively, adds a small capped recency/frequency adjustment (<0.5), applies ambiguity penalty and requires a calibrated minimum. Keep deterministic tie-break by stable code-point ID. Empty/low confidence: show a compact curated discovery or explicitly labeled Recents area without claiming it matched text. Keep Recents and Smart semantically separate even if they share one screen.
- Store static immutable bounded index; merge eligible context asynchronously keyed by editor, locale and composition revision; ignore stale completion. Reuse existing usage model when enabled with per-device storage and reset, and bypass personalization in private fields. No raw context persistence, clipboard access, network or feature-specific contact access. Reuse no-learning defensive boundaries. Record usage once after actual insertion. Treat variant normalization only for scoring, return exact sequence selected.
- UI version 1: Smart category contextual results ahead of Recents, a snapshot upon opening with identity checks, and no auto-reorder under an active finger. Keep ordinary text suggestions dominant. Strip can render two compact Emoji if both pass relevance and independent hit target checks. A third is experimental behind sufficient width and text fallback. Never replace protected next-word/correction candidate or alter SuggestedWords.mWillAutoCorrect or authoritative decoder index. Use explicit replacement vs append selected through InputLogic transaction, support undo and test English/Hinglish round-trip. With narrow or scaled UI show one or none. Category, strip and Emoji search all use same Emoji identity but vary scoring.
- Benchmarks: at least 30 curated positive phrase cases and 30 negative/ambiguous/private cases across English and Hinglish. Measure precision@1 and @3, percentage of unrelated text with an Emoji, coverage, p95 evaluator time and visible latency. Proposed p95 local warmed evaluation ≤5 ms and zero private emissions or text loss, subject to Reno10 measurement. Compare usage-only current grid and source-dictionary strip before judging improvement.

## Glide typing — actual path and replacement evaluation

1. `MainKeyboardView.java` and `PointerTracker.java` provide touch capture. GestureStrokeRecognitionPoints and InputPointers produce recognition data; GestureStrokeDrawingPoints/GestureTrailDrawingPoints/GestureTrailsDrawingPreview own rendered trail. `LatinIME.onStart/Update/EndBatchInput` → InputLogic/InputLogicHandler (sequence prevention) → Suggest/DictionaryFacilitatorImpl → BinaryDictionary handles JNI and gesture composition; confirm exact final candidate vs feedback trail. Record cancellation, glide-to-space, case/locale selection, Delete and landing behavior. Preserve momentary 123 and long-press handling. See [HeliBoard](https://github.com/HeliBorg/HeliBoard).
2. `JniUtils.java` attempts checksum-verified imported library, then system libjni_latinimegoogle, then bundled libjni_latinime for ordinary dictionary operations. `SettingsValues.mGestureInputEnabled` and Settings UI depend on sHaveGestureLib. Bundled AOSP fork's `gesture_suggest_policy_factory.cpp` initializes the factory hook to null. Its presence is not a bundled decoder. Current GestureEnabler gates dictionary, input-field safety, setting and touch exploration. The owner reports imported ARM64 GlideLib decoded on Reno10. Exact test/version and accuracy remain open. Imported Google library is not cleared for public redistribution. Keep existing fallback and no new blind JNI swap.
3. **Leading evaluation candidate:** FlorisBoard's Apache-2.0 StatisticalGlideTypingClassifier at inspected upstream [bac346e8](https://github.com/florisboard/florisboard/commit/bac346e8a5e7ee7104359cebdbce7d4105d3f0fa). It separates endpoint/length pruning, resampling, normalized shape, absolute location and frequency. Manager depends on its Kotlin keyboard/subtype/NLP/co-routine APIs. Evaluate a narrowly adapted classifier interface using brrBoard key centers, lexicon and decoder families. Verify exact file license and third-party data at pin, preserve notices and record modifications before reuse. Avoid copying Floris settings or full NLP/IME. [Candidate source](https://github.com/florisboard/florisboard/blob/main/app/src/main/kotlin/dev/patrickgold/florisboard/ime/text/gestures/StatisticalGlideTypingClassifier.kt) · [License](https://github.com/florisboard/florisboard/blob/main/LICENSE)
4. **Alternatives evaluated:** AOSP bundled gesture hook is a seam, not a complete decoder; filling it in C++ raises ABI/lifetime costs. FUTO Keyboard has source-available terms restricting modification and redistribution, so skip its decoder for this GPL repository unless rights are separately resolved. A compact original template matcher based on published shape+location methods is the fallback architecture if Floris compatibility/accuracy fails. Build endpoint bins with fuzzy nearby start/end keys, length/trajectory filter, resampled points with geometry normalization, location distance and shape distance, frequency and preceding-word prior. Start with fixed-distance scoring then evaluate banded elastic alignment only if speed and quality warrant. Include repeated letters, fast loops, collisions, slips, multiple densities and backtracking. [FUTO license](https://github.com/futo-org/android-keyboard/blob/master/LICENSE.md) · [SHARK2 paper](https://pokristensson.com/pubs/KristenssonZhaiUIST2004.pdf)
5. **Integration proposal:** Existing stroke tracker and trail remain stable. Abstract only the batch recognition boundary if needed. Use layout/subtype-keyed immutable dictionary/geometry indexes prepared off UI thread and invalidated on size, one-hand or locale changes. Do not enumerate binary words during ACTION_MOVE. Normalize x/y from actual key centers and preserve timing for pruning/repeated-letter heuristics. Send queued tentative alternatives with bounded schedule, final only on touch up and current editor; require confidence/margin before auto-commit, reuse existing manual candidates and undo. Avoid result duplication and never auto-fallback to another engine midway through a gesture. Gate capability independent of sHaveGestureLib for the new decoder while keeping historic import usable until acceptance.
6. **Benchmark before replacement:** hold-out ground-truth trace list covering “typing”, close shapes, repeated letters, Indian English and Hinglish, high/low-speed strokes, multiple layouts, false positives on ordinary drag and sentence-space behavior. Include synthetic replay fixtures with normalized coordinates plus consensual test-only captures on owner device with no real text. Report top-1, top-3, exact/forbidden-layout false activation, p50/p95 touch-up-to-candidate and commit latency, frames missed, peak memory, asset size, 16 KB pages and four ABI build/install/load evidence. Compare the licensed candidate, baseline tap engine, and owner-local imported path where permitted. A proposed release gate is no regression on held-out English top-3 or text editing, clear improvement on demonstrated failures with the same trace/layout, p95 final result ≤50 ms warm on Reno10 and no tap-path CPU cost. Calibrate with the owner and record actual sample count. Remove manual import from normal flow only after an ordinary fresh signed install glides offline without side-loading, and preserve upgrade/recovery paths.
