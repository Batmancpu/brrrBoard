## 1. Product outcome and non-negotiable contracts

Deliver one substantially better daily keyboard for the owner's Oppo Reno10 5G / ColorOS setup, while remaining usable on other supported Android devices. Improve the first visible suggestion, continuous three-slot transitions, typing and editing correctness, English/Indian-English/Romanized-Hindi relevance, understandable BR Brain controls, BR Brain/voice reliability, accessibility and perceived speed. Preserve the already polished Frosted Glass visual language; refine verified defects rather than redesigning it for novelty.

Keep the existing com.mangoloads.board package and original Obtainium signing certificate, monotonic release version, native learned dictionaries, user settings, installed offline Parakeet model and in-place update path. No uninstall, data reset, plaintext migration, network permission, cloud text processing or raw-text diagnostic logging. Respect password, no-personalized-learning, incognito, secure-app and host autofill boundaries. A debug APK is not a production release. A passing emulator or CI is not Oppo acceptance.

The neural ContextLM is **not a required shipped feature** of this GO. The current 1.134-million-parameter experimental models lost to the held-out native/n-gram proxy: corrected hard-negative Recall@3 was 20.20% vs 23.19% on tn, 32.24% vs 36.17% on mt, and 13.25% vs 16.87% on hinge; dev calibration chose 0.0 neural weight. Its INT8 executor and personal-feature adapter are inert groundwork. Keep weights absent and loader fail-closed unless a new, truly independent evaluation clears every model gate in section 5. Do not claim “closer to iOS intelligence” merely because a model exists.

The exact iOS 27 private keyboard model, animations and frame timing are not public APIs. Aim for documented behavior and measured feel, not proprietary pixel or model identity. 164 ms in current source is a local design budget, not an Apple measurement. Preserve Android EditorInfo semantics even when they differ from an iPhone screenshot.

### P1 — Make everyday typing immediate and stable

1. Treat suggestion data and rendering as separate state machines. For eligible general prose, show a useful initial row on the first drawn frame, with no entrance animation; do not fabricate a tappable prediction. On every typed prefix, show only fresh matching native candidates immediately, or a visibly literal untappable fallback. Keep the asynchronous native dictionary query nonblocking and replace the preview only when its editor, request, prefix, selection and dictionary generation still match. Never let provisional text become autocorrect.
2. Keep three suggestion slots and dividers attached across one-word, wide-word and five-chip transitions. Update slot content in one atomic UI batch; preserve valid tap tags only for the newest committed candidate set. An empty response after Space may briefly preserve visible ink, but tap targets are revoked immediately and the hold is bounded. Instrument and remove any remaining whole-view rebuild, main-thread dictionary wait, repeated text measurement or invalidate/layout cycle per keystroke that profiling confirms.
3. Define a small explicit row priority: Android autofill and app completions where applicable; protected/editor-specific states; clipboard or command chip when intentionally active; normal word/punctuation row; safe startup fallback. Verify host inline autofill is never disguised as BR Brain text and TalkBack still identifies the provider/action. Restore the ordinary strip after panel, Shift, voice and emoji transitions.
4. Evaluate correction transactions, not just candidate strings. Literal word must remain recoverable after autocorrection. Immediate Backspace or selecting the original spelling reverts only when exact expected text and caret are still present; rejection suppresses immediate reapplication. Handle punctuation, contractions, URL/email/code fields, capitalization, emoji clusters and double-space period without corrupting grapheme boundaries.
5. Add a compact offline replay corpus of scripted taps, pauses, fast Space/Backspace, correction reversals, field switches and composing state, with separate English, Indian English and Romanized Hinglish partitions. Use held-out phrases and no personal data. Report keystroke-to-visible-suggestion p50/p95, blank-row duration and zero stale-tap failures. Target budgets for investigation: first usable row by the initial paint, zero blank interval during eligible continuous typing, p95 first-key response below one 60-Hz frame for the immediate prefix preview, and no material worsening of key-to-commit p95. These are goals to measure, not pre-existing measurements.

Acceptance: continuous usable strip under a 30/60-fps replay, correct visible word on tap, no blank interval above one display frame in an eligible run, no regressions in protected/autofill fields. The real Oppo video must be compared if available; absence of hardware cannot be disguised as visual acceptance.

Freeze corpus hashes and score the installed baseline before modifying ranking.
2. Measure top-1/top-3, MRR, correction acceptance/rejection, false-autocorrect rate, next-word coverage, swipe top-1/top-3 and latency by language/domain. Include a “no change” baseline, existing native/n-gram, personalized native history, experimental neural and calibrated fusion. Prevent leakage across split variants. Report sample counts and confidence intervals; no cherry-picked development set as launch evidence.
3. Preserve the already learned UserHistoryDictionary and explicit personal dictionary in the live candidate path. Verify prior-version upgrade, preference OFF, incognito/no-learning, reset, backup/restore and secure-app transitions. User history should influence ranking only where allowed. Keep contacts, app labels and host completions out of experimental model input. Make BR Brain dashboard metrics honest about source, sample window, skipped private events and unavailable model; never show a fabricated “accuracy” score.
4. Tune existing native candidate pruning, normalization, case handling and calibrated confidence first if held-out traces expose concrete errors. In Hinglish, protect deliberate spellings and code-switching; do not force a Hindi correction onto valid English or vice versa. 5. Acceptance: published before/after counts and metrics, zero privacy violations, no false superiority claim, native suggestions remain instant. A rejected model is a successful gate, not unfinished work.

## 5. Blind spots and decisions already made

- **Source truth vs historical handoffs:** several 17–20 November plans contain old release numbers, paused GTCRN descriptions and previous GO/hold states. Newest main and v1.0.216 are baseline; do not restart completed batches or revive superseded instructions.
- **Apple parity:** public Apple documents confirm user-visible behavior, not their training corpus, hidden ranking weights or motion curves. LTMorphingLabel is an iOS 8 community impression. Use objective user outcomes and measured reference video where possible.
- **Language availability:** Apple QuickPath/inline/prediction varies by locale. Do not promise identical English/Hinglish feature availability merely because English iOS screenshots show it.
- **Privacy breadth:** Android's no-learning flag, password variation, secure-app list, incognito, user opt-out, clipboard and voice recovery each need independent tests. A single “private mode” boolean is not sufficient evidence.
- **Personalization at upgrade:** preserve native history and exact user entries. No training or benchmarking on personal editor contents; no export of native dictionaries to make neural features work.
- **Autofill and host editors:** Android owns inline autofill payloads and EditorInfo action semantics. Text may be rejected by third-party InputConnections; never treat a successful IPC call as proof of applied text.
- **Voice acoustics:** the owner has accepted brrClean on one phone condition; that is not a controlled WER improvement. Dual microphone fusion and Ultra 0.6B model expansion remain separate evidence-driven projects, not automatic scope.
- **APK continuity:** original signer and package are essential for updating the installed app. Model-free update and first-install model provisioning are separate paths.
- **Marketing drift:** README, docs and release notes must describe current source and actual signed assets. The present README voice FAQ is stale.
- **Performance causality:** no claimed speedup from static font bytes or fewer CI jobs alone. Record before/after signed size, real frame timing and key path latency. Emulator measurements do not certify Oppo thermals, blur or microphone routing.
- **Unbounded work risk:** the GO commits to this finite plan and a release. Additional speculative models, new themes and unrelated feature requests require a separate plan, after this delivery.
