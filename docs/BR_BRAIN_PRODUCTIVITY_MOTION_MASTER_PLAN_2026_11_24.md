## M0/M1: common contracts
Introduce narrow editor session token (reuse editorGeneration + connection identity + selection epoch where selection matters), privacy capability snapshot, monotonic time source injected into tests. All async work captures token; revalidate immediately before application; no host call on draw or touch hot path. Private capability denies capture, learning, recall, derived suggestions/history and contextual transformation in password, no-personalized-learning, incognito, locked, protected or vault fields; global denial overrides profile. Clear ephemeral buffers on real editor finish/start, connection change, hide/detach, lock or privacy changes; do not treat ordinary layout rebuild as new editor, but conservative clear on ambiguous restart. One clear method invoked from existing lifecycle owners; cancellation generations prevent late writes. No raw text in diagnostic reports/exception logs, no raw touch points persisted, no analytics. New local data excluded from backups and protected by CE/no-backup storage; explicit reset invalidates pending writer revision. Sensitive flags hide previews but are not security encryption. Tests fake clock and connection, private policy matrix, stale callback, lock and reset.

## M3: BR Brain Adaptive Touch
Gboard's published research (Sivek & Riley, 2022 https://arxiv.org/abs/2209.11311 ; https://research.google/pubs/spatial-model-personalization-in-gboard/) adapts Gaussian spatial-model means and optionally covariance, uses normalized offsets, clustering, prior/weighting and combined language/spatial scoring. Exact current proprietary code, key correction thresholds and training are not public. Independently implement published mechanism, not copy proprietary code or claim parity. Tap only first; swipe, symbols, private gesture, mic, trackpad, popups, repeats, accessibility events and precise centered taps unaffected.
New proposed latin/brain/AdaptiveTouchModel, TouchLearningSession, AdaptiveTouchStore and policy. Geometry signature from existing KeyboardId layout/subtype/width orientation/one-handed/split; normalize residual r=((x-cx)/w,(y-cy)/h). Group neighboring keys (initial six-ish spatial groups, choose via held-out data), then shrink each cluster toward global/zero prior. Optional per-key residual only with strong evidence. Initial tunable candidate parameters (not Google values): 32–64 confirmed samples per cluster; prior weight 32; clamp mean per-axis ±0.18 key dimensions, floor variance, cap update magnitude and bounded decay. Score = 0.5*(r-mu)^T invSigma (r-mu) plus logdet if covariance varies; prior/default if singular/unknown. Keep covariance fixed initially, learn regularized covariance only if offline gate improves. No raw sequence, word, timestamp per tap, package identity or coordinate history stored. Persist only aggregate n/sums/second moments/decay/schema, bounded profiles, AES-GCM no-backup CE via purpose-separated vault. Immutable in-memory snapshot read without lock/IO in hot path; write debounced off UI with revision guard, opt-out/erase cancels pending writes. No persistence from locked/private contexts, fail closed.
Use existing composing pointer x/y and confirmed tap events; training labels from explicit candidate selection / verified immediate correction (same-length unambiguous adjacent-key alignment only), plus conservative unchanged dictionary words after validation, never train on auto-correct prediction alone or synthetic center coords; use transient bounded per-word points, clear at commit/cancel/editor/timeout. Do not re-enable retired GestureConsumer. Score in native tap path if native interface permits (inspect scorer and add versioned params without changing GLIDE ABI); otherwise use conservative candidate-relative spatial rescoring of existing native tap candidates plus boundary-only primary key correction in KeyDetector for eligible letters. Do not globally shift coordinates or override exact interior taps; ensure decoder isn't double-correcting (single spatial contribution). Preserve literal original fallback and native autocorrect threshold until benchmark proves. Split modes, languages, layout and landscape isolation; no app-scoped touch learning needed. Pseudocode: if eligible && edge && trained: select among nearby eligible letter keys by bounded likelihood improvement; otherwise legacy hit; decoder gets consistent snapshot; confirmation updates stats off-path, publishes immutable next snapshot. 
Phased rollout: shadow synthetic replay only (no private data logging) → opt-in learning with score disabled → opt-in apply when gate passes → default-on only after owner acceptance. BR Brain dashboard shows Enabled/Learning/Ready and reset, protected numeric counters optional; no typed samples. Tests: synthetic shifted distributions, rare keys/zero samples, left/right/thumb, outliers, drift, different layouts, covariance singular, exact centered taps, disabled equivalence, typo rejection, cancellation, encrypted roundtrip tamper and reset race, no log/backup leaks. Offline fixed English/Hinglish synthetic corpus with simulated offsets: compare character/word error, wrong autocorrections, top-k, p95 hot path, no unshifted accuracy regression; propose >=5% relative CER improvement on offset corpus and <=0.2 percentage point regression on clean corpus, tune on dev set not test set. Real-device owner A/B on non-sensitive prompts, no captured private typing traces. No accuracy promise before measurement.

## M6: smart clipboard — private by design
Proposed ClipboardEntityExtractor: pure local deterministic bounded parser on explicit user tap "Extract" on a selected current plain-text item, not background scanning, default off/tap-to-reveal. Accept links (http/https only; never fetch), email, phone, OTP only with explicit code context (4–8 digits conservative), optional explicit labeled address (no geolocation service). No cloud, no contacts/notifications/SMS permissions, no URI/provider dereference, regex DoS bounds max 4KiB input, <=8 entities, linear scans/bounded regex. Show masked OTP/phone/email and host-friendly type labels, explicit reveal/paste. Use ranges over current clip, not a second database or detached text copies; RAM-only <=30s or earlier close, clip changed, editor changed, hide, lock, private. Re-read same content/receipt and verify active epoch before direct RichInputConnection commit; no writing extracted data back to Android Clipboard by default, no automatic paste/action/open/share. Reject Android sensitive-flagged clips and private/no-learning/locked fields entirely. OTP-like and other obvious secrets (password/credential/recovery/payment/key tokens) excluded before NEW history writes, use conservative deny/avoid misclassifying ordinary long numbers; flagged sensitive clips not processed even via extraction. Ordinary OTP from unflagged current system clip can be extracted only on explicit foreground action, masked, never auto-history/pin/preview/learning. Existing historical clips may already contain unflagged secrets; do not promise retroactive detection; exclude obvious sensitive entries from extraction history and offer explicit cleanup with consent. Unknown classification can fail safe; parser cannot guarantee all secrets recognized. No extra derived records, analytics, backups, search index, screenshots or logs. Existing system clipboard not under keyboard control; don't clear other apps' clip on timer. Reuse ClipboardPrivacyPolicy and existing receipts; before addClip guard and recentTextClip guard separately; do not change existing image support. Ordinary clipboard vault future: opt-in app-layer encryption with new purpose-separated Keystore key, crash-safe transactional migration (verified ciphertext then purge plaintext DB/WAL/images, no insecure fallback; backup compatibility explicit, no deleting pins silently), search on bounded decrypted session memory, categories/edit manual only, retention enforced.
