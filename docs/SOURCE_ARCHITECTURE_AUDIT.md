## Source-confirmed risks and ranked hypotheses

1. **Shortcut panel guard is explicit.** KeyboardSwitcher.onToggleKeyboard around L1447 rejects ACCESS_POINT from Emoji and Clipboard. BoardFooterView has a separate PopupWindow arc and direct key dispatch. Trace the exact owner gesture before deciding which path is blocked. L1160 Clipboard hides Emoji and tabs; the shown branch does not call stopEmojiPalettes there, whereas alphabet does. Check stale search state and repeat navigation. Do not conflate the arc with the older ACCESS_POINT full panel.
2. **IME dismissal and panel animation have distinct timing.** KeyboardSwitcher.transitionToPanel cancels prior animation, mutates view visibility synchronously and fades the target from 0 over 350 ms. A rapid transition or stale end callback may clear the current animation owner or leave stale alpha. Add generation/visibility verification before tuning. LatinIME.onComputeInsets uses wrapper/panel plus strip, persistent row, footer and frame bottom padding, with last-height fallback. Read actual rectangles to detect a footer/inset counted twice, stale fallback after editor/config changes, or a frame temporarily invisible during the transition.
3. **Tail of asynchronous work.** Dictation already cancels at multiple lifecycle boundaries and guards sessions. Clipboard suggestions, async inline inflation, dictionary suggestions, timer-driven footer menu, gesture decoder and resize animations may outlive a view/editor. Reproduce observer ordering. Establish editor epoch invalidation only where needed, and keep same-editor restart semantics deliberate.
4. **Emoji paging is a source-supported cause.** EmojiPalettesView L218 attaches PagerSnapHelper to whole-page items, including consecutive pages in one category. Category indexing, per-page touch hitboxes and variants must migrate together if page ownership changes. See R2.
5. **Toolbar state.** Latest source hid unavailable choices and migrates stale preferences in ToolbarUtils/settings/strip/menu. Existing ordinal values and persisted user layouts are compatibility surfaces. Test upgrades and third-party editors before editing again.
