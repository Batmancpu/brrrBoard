The owner expressly forbids fixing this by keeping its app/service running in the background. They also request a fixed circular mic surface (not cut off by key strip), only the MIC glyph glowing/pulsing, and a visible, tappable **Cancel** label instead of “Recording”. **Source plan implemented:** brrSpeak gains `BoardAudioWakeProvider` at `content://com.mangoloads.speak.boardaudio`, exported but call-only; it validates Binder UID against exact brrBoard package and rejects all CRUD/file-like methods. A one-time `prepare-recorded-audio` call launches the *cold* app process through Android's normal ContentResolver path without a persistent background service or activity. brrBoard removes the brittle pre-capture `GET_SERVICES` probe, asynchronously calls this provider after capture, then explicitly binds the already-existing authenticated `BoardRecordedAudioService`, transferring only the completed read-only PCM descriptor as before. If the provider is absent/refused it attempts the old direct bind for diagnosability; old brrSpeak versions below 142009 are explicitly rejected. No keyboard text/context, clipboard, network permission, or second microphone is added.

**UI:** `FooterStatusRingDrawable` fixed radius 18dp/no outer ring bloom, mic-centered inner 15dp tint glow; `FooterMicPulseDrawable` scales just the tinted glyph by at most 8.5%, never the ImageButton background. Processing is visually still. `BoardFooterView` makes the centered **Cancel** text an actionable discard with accessibility and minimum 72dp tap width; normal second mic tap stops/sends. Offline long-press blue voice and all unrelated keyboard behavior remain untouched.

**Test gate:** pure protocol version/wake constants, wrong-UID package policy on brrSpeak, bounded icon scale and prior PCM regression tests; app compile, debug/unit tests, original-signer release verification and exact APK asset IDs still required on this commit. **Real ColorOS cold-start remains unverified** until owner installs new brrSpeak first and brrBoard second and tests after swiping brrSpeak away (not force-stop), then cancellation/rapid tap/editor changes. On explicit OS force-stop or OEM autostart denial, neither app can silently override the user's system choice. Do not claim phone success or signature continuity for ephemeral-signed brrSpeak.
