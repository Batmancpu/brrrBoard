# Settings 2.0 — proposed design brief (2026-11-25)

Status: proposal, pending owner approval; no runtime/UI changes. Owner requested a full premium Apple-like settings overhaul: airplane-level control without a cockpit on the main screen, like a PS5 controller; advanced cockpit controls remain accessible. Function, aesthetics, reliability, responsiveness, privacy, and low friction all matter. The three checks are flexible principles, not mandatory gates for every feature.

## Current architecture (reviewed at 9af6ac75)
Jetpack Compose MainSettingsScreen, SettingsBrandTheme Pearl/Midnight, SettingsNavHost, SearchScreen and SettingsContainer, FocusedSettingsScreens, BrainDashboardScreen and KeyboardTryoutCard. Existing search maps preference keys to routes and breadcrumbs; existing protected routes use RAM-only authorization, deadline and FLAG_SECURE. Current main settings expand a long advanced list inline. Public Brain currently mixes manual templates, replacement, clipboard vault and editing gesture controls. Existing CI checks fixed palette, routes, setup state, breadcrumbs, privacy and glass behavior. Keep all contracts or deliberately update tests with equivalent coverage.

## Information architecture
Root: one live keyboard tryout hero (actual active theme, optional action, no automatic IME opening), conditional setup only if keyboard not enabled/default; BR Brain summary; Appearance, Typing, Voice, Clipboard, Sound & haptics; Privacy & security; Advanced; About. Search global with meaningful synonyms and breadcrumbs. No persistent bottom nav for a single settings hierarchy. All common adjustments reachable in one or two navigation steps. No generic 'enable intelligence' master switch that silently changes unrelated preferences. Main summaries reflect actual state only.

Appearance: visual cards for existing themes, layout and scale preview, typography, glass; detailed colors/blur/geometry under contextual advanced. Typing: corrections, suggestions, swipe, languages/layout, keys, gestures, toolbar; advanced behavior in relevant group. Voice: actual readiness, engine selection/install if necessary, hold-to-talk and optional auto-send; model/noise/diagnostics advanced. Clipboard: history, pins, screenshots, retention, voice recovery description; automatic encryption only after safe migration implemented, never falsely label current opt-in vault protected. Sound: haptics, sound, intensity with real previews. Brain public: local status and understandable behavior, no learned plaintext/metrics/experimental controls; auto-learning changes require separate verified implementation. Protected Brain: deliberate existing code flow, per-app learned data, inspect/forget/reset, detailed metrics and experiments; no protected content indexed in public search. Privacy: protected apps/incognito, storage scope/permissions, data deletion; no security downgrade by appearance changes. Advanced: dedicated organized screen not huge home expansion; layout, interaction, language/dictionary, engine, compatibility, diagnostics, backup/reset with existing routes and preference keys. About: versions, changelog, help, licensing.

## Visual system
Warm-neutral light surfaces / near-black graphite dark surfaces with restrained sapphire accent and semantic privacy/voice tones. Actual keyboard themes remain independent. Large 30–34sp title, 16–17sp row title, 13–14sp supporting text; 16–20dp outer margins, 18–24dp group corners, 48dp minimum accessible targets, adaptive text size/RTL/insets. One coherent licensed icon set (existing Material Symbols/brrBoard vectors), no Apple assets. Glass only navigation/floating elements or preview where meaningful; static opaque fallback for reduced motion, accessibility or expensive GPU paths. Use compact grouped rows, inset separators, current-value summaries, clear controls and one coherent transition system, Android back/predictive back where supported. No decoration-driven heavy effects; no fake statuses. Avoid inventing new presets that overwrite existing settings. Use existing preferences and exact installed values; no automatic reset. Keep protected access unchanged and exclude search terms/typed samples from logs and storage.

## Implementation order
1. Inventory every preference key/route and public/protected visibility; create parity map, screenshot baseline, tests. 
2. Consolidate shared components and palette, root, navigational hierarchy and search. Keep existing route identifiers/backup schema stable; avoid duplicated settings.
3. Redesign every destination, dialogs, lists, sliders, model states, keyboard preview, accessibility and onboarding/empty/error states.
4. Implement automatic-first Brain features separately with verified privacy gates, encrypted migration and opt-out, conservative suggestions and no silent destructive replacements. No claim they are currently automated.
5. Verify all existing preference values preserved; navigation/search coverage; protected route tests, lock/expiry, no public sensitive index; light/dark/font scale/RTL/rotation/low-memory; no added typing hot-path work, no runtime polling while pages hidden. Physical Reno 10 5G screenshots and performance testing; release exact-commit debug/unit/signing gates. Main only, same signing and package. 


### 2026-11-25 — Settings 2.0 implementation, design system and navigation pass
Owner approved complete premium iOS-like, blurred settings overhaul with keyboard identity, toggle and slider motion, all pages, efficient UX; confirmed Voice Recovery works and requests strict expiry. Implemented neutral Pearl/Graphite surfaces while preserving original sapphire accent, common rounded shapes/type, existing Haze header (22dp, opaque pre-S fallback), search styling and protected title-hold path, grouped registered preference rows with stable keys, accessible 48dp iOS-inspired green pill switches (motion-scale aware), native slider semantics/snapping with custom capsule track and white thumb, shared rounded dialog geometry. Applied common controls to direct Voice, Brain, protected/privacy, editing, rule and Glass Studio controls. Home is compact; dedicated Typing and Advanced hubs preserve existing route IDs and all preference keys; keyboard preview uses actual IME on explicit tap, static glass-like hero without indefinite shimmer; Appearance places Glass Studio first and adds live tryout; existing groups retain all options. Public Brain folds manual controls without pretending automatic templates/replacement/encryption are implemented. Clipboard explains 60s RAM-only recovery. No new keyboard theme, no storage schema/default/signing/package change. Tests for grouping and exact-source build/signing required. Current Voice Recovery uses monotonic expiry, handler purge and screen-off clear; JVM cannot guarantee forensic zeroization. Device acceptance for visual layout, switch/slider and protected routes is pending. Additional per-screen polish and automatic Brain implementations are separate work; this pass is not a claim that every custom destination is individually redesigned. Main only.
