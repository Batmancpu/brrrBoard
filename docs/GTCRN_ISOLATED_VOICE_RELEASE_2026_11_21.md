## Code and exact behavior

- VoiceNoiseMode.kt: user-selected ANDROID default or GTCRN; used for both normal blue dictation and BR Brain lab. Old Android-enabled pref remains honored in Android mode.
- VoiceCaptureNoiseReduction: capture-time Android effect is attached only in ANDROID mode. The Android API does not accept prior PCM for postprocessing; it cannot deliver an exact same-buffer Android-versus-GTCRN A/B comparison. Firmware/earbud preprocessing may still happen in either mode.
- KeyboardPcmAudioSource: unchanged one 16 kHz mono AudioRecord. OfflineBoardDictation: only after Stop, send eligible short PCM (up to 12 seconds/384,000 bytes) asynchronously to GtcrnVoiceBridge. On valid result feed enhanced PCM to existing Parakeet; on crash/timeout/bind failure, feed original PCM. Longer speech bypasses GTCRN and transcribes in full. Editor and generation guards remain in place.
- GtcrnVoiceService: non-exported child process :brr_voice_gtcrn, not the keyboard process. Bound Messenger IPC, one native sherpa-onnx instance on background-priority thread, at most 384 KB input and output per Binder message. Parent watchdog 17 seconds; child hard timeout 15 seconds; child terminates itself after result. Invalid shape/sample-rate/output, exception or native abort falls back. No raw speech, messages or trace to disk, logs or network; all PCM copies wiped.
- VoiceNoiseLab: a single explicit <=12-second take, captured only once. GTCRN processes the exact same original bytes after Stop; users can replay/score original and enhanced separately with installed Parakeet. Android mode captures with OS effect and can replay/score that capture, but is a separate take. Reject a missing/rejected Bluetooth input, a confirmed wrong microphone source, API 29+ client silencing and near-zero PCM; label Android-unverified routes honestly.
- BR Brain dashboard and child screen: show selected actual mode and Android's live active/idle state, with no false permanent “GTCRN paused” label. One-take lab replaces six confusing cards. On-screen explanation clarifies that model fallback is not measured audio improvement.
